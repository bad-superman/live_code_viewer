# 危险命令过滤功能需求文档

## 功能概述
**危险命令过滤**是 Live Code Viewer 终端同步功能的安全增强组件。当观众端通过双向终端输入功能向主机端发送终端命令时，该功能会检测并过滤可能对主机系统造成危害的危险命令。

## 背景
当前 Live Code Viewer v0.1.9 已实现双向终端输入的基础设施，但存在以下问题：
1. 终端输入处理尚未完全实现（技术债务）
2. 缺乏对观众端发送命令的安全检查
3. 主机端可能面临恶意命令的风险

## 目标
1. **安全防护**：保护主机系统免受恶意终端命令的影响
2. **可控协作**：在保持协作便利性的同时提供安全边界
3. **透明操作**：用户清楚了解哪些命令被过滤及原因
4. **可配置性**：允许用户根据需求调整过滤规则

## 功能需求

### 1. 命令分类系统
- **安全命令**：允许执行的普通命令（如 `ls`, `cd`, `cat`）
- **警告命令**：需要用户确认的命令（如 `rm`, `chmod`, `sudo`）
- **危险命令**：自动阻止的命令（如 `rm -rf /`, `format`, `dd`）
- **自定义规则**：用户可定义自己的命令分类

### 2. 过滤机制
- **实时检测**：在命令发送到主机终端前进行检测
- **模式匹配**：支持正则表达式匹配命令模式
- **上下文感知**：考虑命令参数和上下文（如 `rm` vs `rm -rf /`）
- **多层过滤**：内置规则 + 用户自定义规则

### 3. 用户交互
- **透明提示**：当命令被过滤时，向观众端显示原因
- **确认对话框**：对于警告命令，提供确认机制
- **过滤日志**：记录所有被过滤的命令和原因
- **设置界面**：VS Code 设置中提供过滤规则配置

### 4. 规则管理
- **内置规则库**：预定义常见危险命令模式
- **规则导入/导出**：支持规则集的分享和备份
- **规则优先级**：处理规则冲突的优先级系统
- **规则测试工具**：测试命令是否会被过滤

## 技术需求

### 1. 架构设计
- **客户端过滤**：在观众端进行初步过滤
- **服务端验证**：在主机端进行最终验证
- **可插拔架构**：支持未来扩展更多过滤引擎

### 2. 性能要求
- **低延迟**：过滤操作增加延迟 < 10ms
- **高吞吐**：支持快速连续命令处理
- **资源效率**：内存使用 < 5MB

### 3. 集成点
- **终端消息处理**：集成到现有的 `handleTerminalInput` 方法
- **协议扩展**：可能需要新的协议消息类型
- **UI 集成**：状态栏显示过滤状态

## 非功能需求

### 1. 安全性
- **防绕过**：确保过滤机制不能被轻易绕过
- **安全默认值**：默认启用严格过滤模式
- **安全审计**：所有过滤操作可审计

### 2. 可用性
- **易配置**：用户无需专业知识即可配置
- **清晰反馈**：过滤原因明确易懂
- **学习模式**：可暂时关闭过滤进行学习/演示

### 3. 可靠性
- **故障安全**：过滤失败时默认阻止命令
- **恢复能力**：规则损坏时可恢复默认规则
- **兼容性**：与现有终端功能完全兼容
